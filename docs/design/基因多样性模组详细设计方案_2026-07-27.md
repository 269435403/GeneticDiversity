# RimWorld 1.6「基因多样性」模组详细设计方案

> 调研与方案日期：2026-07-27  
> 暂定中文名：**基因多样性**  
> 暂定英文名：**Genetic Diversity**  
> 暂定 `packageId`：`yyyyy.geneticdiversity`  
> 暂定程序集/命名空间：`GeneticDiversity`  
> 暂定 Harmony ID：`yyyyy.geneticdiversity`  
> 必需内容：RimWorld 1.6、Biotech、Harmony  
> 可选兼容：Humanoid Alien Races（HAR）、阵营种族多样性、阵营文化多样性以及各类已加载基因模组

---

## 零、不可变核心公约：当前存档系谱优先

本模组的长期目标是模拟一个世界在数百、数千年中的遗传扩散，而不是对已加载 GeneDef 做无差别抽签。今后所有阶段都必须遵守：

1. 随机可遗传变体首先来自当前存档已经实际存在的异种/族群 Endogenes，并按实际出现频率及同 Race/同阵营关系加权；
2. 原版 Human/Xenotype 与 HAR Race/Xenotype 同等适用，HAR 接入后不得继续把 HAR Pawn 排除在世界系谱池之外；
3. 只有当前存档系谱池为空、候选不兼容，或机制明确属于低概率新突变时，才使用全局 Def/Xenotype 回退池或突变池；
4. 为了命中概率不得删除核心基因、替换 Xenotype、转换 Xenogenes、放宽冲突/前置/代谢/Race 安全规则；
5. 新差异优先作为 Endogene 交给原版父母遗传继续传播，从而形成家系与族群历史。

阶段 2 的 10% 出生突变属于第 3 条的明确“低概率新突变”分支；阶段 3 的 HAR 工作必须首先扩展当前存档系谱池，而不是建立脱离存档历史的 HAR 全 Def 随机池。

## 一、结论：这个创意值得做，但不能直接“给每个人随便塞基因”

这个方向与前两个模组非常契合：

- **阵营文化多样性**解决“同一阵营的人为什么文化完全一致”；
- **阵营种族多样性**解决“同一阵营的人为什么 Race/异种类型完全固定”；
- **基因多样性**则解决“即使 Race 和异种类型不同，为什么同一异种类型内部仍然像复制出来的一样”。

原版确实已经有完整的亲代遗传机制，但它主要服务于**自然出生的孩子**。普通袭击者、商队成员、访客、世界人物等成年 Pawn 通常是先按阵营/PawnKind 选中一个完整 `XenotypeDef`，再把这个异种类型的整套基因原样装上，因此同一异种类型内部几乎没有“家族差异”“隐性遗传差异”或“族群中的小变体”。

因此，本模组最合理的定位不是替换原版异种类型，而是：

> **保留 Race、异种类型与其核心基因，在其上增加少量、可遗传、受种族兼容规则约束的系谱基因差异；这些差异随后继续由原版父母遗传机制传给孩子。**

推荐采用“**核心基因 + 可变基因位点 + 低概率突变**”模型，而不是把每个 Pawn 的全部基因重新随机一次。这样既能形成多样性，也不会让猪人突然失去猪鼻、沃芬随机失去其专属机制、任务人物失去固定异种身份，或让 HAR 身体部件基因被错误放到不兼容 Race 上。

## 二、中文术语与代码映射核验

| 方案中的中文概念 | 原版/HAR 代码对象 | 说明 |
|---|---|---|
| Race / 生物种族 | `ThingDef`，通常检查 `race.Humanlike` | 原版人类是 `ThingDefOf.Human`；HAR 种族通常是 `ThingDef_AlienRace` |
| 异种类型 | `XenotypeDef` | 一套预定义基因及是否可遗传等规则，不等同于 HAR Race |
| 基因定义 | `GeneDef` | 定义属性、能力、外观、代谢、冲突、前置基因与自定义 `geneClass` |
| 实际基因实例 | `Gene` | 装在具体 Pawn 的基因追踪器中 |
| 系谱基因 | `Pawn_GeneTracker.Endogenes` | 原版亲代遗传会从这里取基因；本方案新增的可遗传差异默认也放这里 |
| 异种基因 | `Pawn_GeneTracker.Xenogenes` | 通常来自不可遗传异种胚芽；原版孩子不会从父母的异种基因直接继承 |
| 基因追踪器 | `Pawn_GeneTracker` | 管理异种类型、系谱基因、异种基因、冲突覆盖与存档 |
| 原版遗传入口 | `PregnancyUtility.GetInheritedGenes` | 按父母系谱基因计算孩子的遗传基因 |
| 出生生成入口 | `PregnancyUtility.ApplyBirthOutcome` | 把遗传结果作为 `forcedEndogenes` 交给 `PawnGenerator` 生成新生儿 |
| HAR 基因兼容判定 | `AlienRace.RaceRestrictionSettings.CanHaveGene` | 决定某个 `GeneDef` 能否以系谱/异种基因形式存在于指定 Race 上 |
| HAR 异种类型兼容判定 | `AlienRace.RaceRestrictionSettings.CanUseXenotype` | 决定指定 Race 能否使用某个 `XenotypeDef` |

注意：**HAR Race 与 Biotech Xenotype 是两条不同轴线。**一个鼠族 Race 可以有多个鼠族异种类型；同一个人类 Race 也可以有智人、猪人、妖魔等多个异种类型。新模组必须同时理解这两层，不能把 Race 与 Xenotype 混为一谈。

## 三、原版代码调查结果

### 3.1 普通人物为什么是“固定基因”

原版人物生成的关键流程位于：

- `Verse/PawnGenerator.cs`
- `RimWorld/Pawn_GeneTracker.cs`
- `RimWorld/XenotypeDef.cs`

流程大致如下：

1. `PawnGenerator.GetXenotypeForGeneratedPawn(request)`：
   - 优先使用 `ForcedXenotype`；
   - 然后考虑 `ForcedCustomXenotype`、`AllowedXenotypes`；
   - 否则从阵营、PawnKind、主要文化提供的 `xenotypeSet` 中按权重选择；
   - 最终无结果时回退 `Baseliner`。
2. `PawnGenerator.GenerateGenes(pawn, xenotype, request)`：
   - 调用 `pawn.genes.SetXenotype(xenotype)`；
   - 加入自定义异种类型基因；
   - 加入请求强制的异种基因/系谱基因；
   - 最后补皮肤色与发色基因。
3. `Pawn_GeneTracker.SetXenotype`：
   - `XenotypeDef.inheritable == true` 时，异种类型里的基因加入为系谱基因；
   - `inheritable == false` 时，异种类型里的基因加入为异种基因。

所以普通成年 Pawn 的基因大多是“选中哪一个异种类型，就完整获得哪一整套基因”。原版没有再给每个成年 Pawn 做一次模拟亲代遗传，也没有按当前世界基因频率制造同类型个体差异。

### 3.2 原版父母遗传的实际算法

`PregnancyUtility.GetInheritedGenes(father, mother, out success)` 的核心规则如下：

1. **只读取父母的系谱基因**，不读取异种基因。
2. 跳过：
   - `EndogeneCategory.Melanin`（皮肤色由专门流程处理）；
   - `biostatArc > 0` 的超凡基因。
3. 某个基因只有一名亲代拥有时，继承概率为 **50%**。
4. 父母双方都有同一个基因时，继承概率为 **100%**。
5. 每次候选结果都会：
   - 删除缺少 `prerequisite` 前置基因的基因；
   - 计算未被覆盖的系谱基因总代谢；
   - 要求结果位于 `GeneTuning.BiostatRange`，即 **-5 到 +5**。
6. 如果代谢不合法，会重新随机，最多尝试 50 次。
7. 皮肤色与发色有独立遗传逻辑。
8. 近亲关系还会额外产生 `Inbred` 基因概率。

### 3.3 新生儿怎样获得遗传结果

`PregnancyUtility.ApplyBirthOutcome` 会：

1. 使用传入的怀孕/胚胎基因列表；如果没有传入，则调用 `GetInheritedGenes`；
2. 把结果作为 `PawnGenerationRequest.ForcedEndogenes`；
3. 强制以 `Baseliner` 为初始异种类型生成新生儿，再装入遗传系谱基因；
4. 如果父母满足同一可遗传异种类型条件，则仅用 `SetXenotypeDirect` 恢复异种类型身份；
5. 如果父母应当形成混血，则设置 `hybrid = true`。

这说明最稳妥的兼容路线是：

- **不重写原版遗传算法；**
- 给成年/世界生成 Pawn 增加少量系谱变体；
- 让这些变体自然进入父母的 `Endogenes`；
- 以后孩子由原版算法按 50%/100%、代谢、发色、肤色与近亲规则继续遗传。

## 四、设计目标与明确不做项

### 4.1 目标

1. 新生成的人形 Pawn 在保留 Race 与异种类型核心身份的前提下产生个体差异。
2. 默认每个“可变基因位点”有：
   - **90%** 从当前存档的常见基因池获得；
   - **10%** 从当前存档尚未出现的兼容基因中作为突变获得。
3. 新增差异默认是系谱基因，能继续被原版生育系统遗传。
4. 兼容原版所有可遗传/不可遗传异种类型。
5. 兼容 HAR 的 Race 基因白名单、黑名单、类别限制、化学品限制和异种类型限制。
6. 与“阵营种族多样性”共享最终 Race/异种类型结果，而不是重新选一次 Race/Xenotype。
7. 与“阵营文化多样性”保持正交：文化不自动决定基因，基因也不自动决定文化。
8. 默认只影响新生成 Pawn；旧存档人物不被自动批量改写。
9. 移除本模组后，不因为本模组自建 GeneDef 而损坏存档——推荐初版**不新增任何实际功能基因**。

### 4.2 不做项

1. 不删除或替换异种类型的核心基因。
2. 不把异种基因自动改造成系谱基因。
3. 不对机械体、动物、非人形实体、无 `Pawn_GeneTracker` 的 Pawn 处理。
4. 不默认给超凡基因做自然突变。
5. 不默认跨 Race 传播耳朵、尾巴、身体框架等结构基因。
6. 不自动让某种文化、意识形态、国籍或阵营绑定某种“优劣基因”。
7. 不在初版大规模修改旧 Pawn。
8. 不用 Transpiler 重写原版遗传方法；除非后续版本没有其他可维护入口。

## 五、推荐机制：核心基因 + 可变位点 + 原版遗传

### 5.1 核心基因

以下基因视为“核心”，初版不删除、不替换：

- 当前 `XenotypeDef` 自带的基因；
- `ForcedEndogenes`、`ForcedXenogenes`；
- 玩家明确设计的 `ForcedCustomXenotype`；
- HAR `generalSettings.raceGenes` 强制加入的 Race 基因；
- 已存在于 Pawn 上的所有基因；
- 兼容配置标记为不可变的种族结构基因。

本模组只尝试**追加**少量兼容系谱基因。追加后如果会产生冲突、代谢越界、缺少前置或角色功能失效，就放弃该候选，而不是移除原有核心基因来给它腾位置。

### 5.2 可变位点数量

建议标准强度的初始分布：

| 新增可变位点数 | 概率 |
|---:|---:|
| 0 | 20% |
| 1 | 55% |
| 2 | 20% |
| 3 | 5% |

这意味着约 80% 的普通新生成 Pawn 至少有一个个体变体，但大多数只有一个，不会把异种类型搅成随机基因包。

设置页可提供“保守 / 标准 / 高多样性”三个预设，而不是一开始就给玩家十几个滑条：

- 保守：0～1 个位点；
- 标准：按上表；
- 高多样性：1～4 个位点。

### 5.3 90% 常见基因、10% 突变的准确含义

推荐把 90/10 应用于**每一个新增可变位点的来源选择**，而不是要求最终基因组中 10% 的全部基因都是突变。后者会让拥有十几个核心基因的异种类型平均再产生一两个突变，强度过高。

伪代码：

```text
slots = RollVariationSlotCount()
for each slot:
    if Rand.Chance(0.90):
        candidate = SelectFromStandingGenePool(pawn)
    else:
        candidate = SelectFromMutationPool(pawn)

    if GeneSafetyValidator.Accepts(candidate, pawn, request, currentGenes):
        pawn.genes.AddGene(candidate, xenogene: false)
```

设置中的“突变比例”默认 10%，玩家可调整；常见基因比例始终为 `100% - 突变比例`。

## 六、“当前存档基因池”的定义

只读取 `DefDatabase<GeneDef>` 会变成“当前加载模组的所有基因”，不等于“当前存档中各个种族实际拥有的基因”。因此需要分层构建基因池。

### 6.1 第一层：当前存档实际出现的基因

定期从 `PawnsFinder.AllMapsWorldAndTemporary_Alive` 扫描：

- 只统计人形、存活、有基因追踪器的 Pawn；
- 按 `pawn.def`（Race）统计；
- 统计 Pawn 的系谱基因；
- 异种基因默认不进入“自然遗传常见池”；
- 同一个基因出现次数越多，抽取权重越高。

建议权重：

- 与目标 Pawn 同阵营、同 Race：基础计数 ×4；
- 同 Race、不同阵营：基础计数 ×2；
- 其他当前已出现 Race：基础计数 ×1。

这样既符合“世界共同基因库”，又能保持同 Race、同族群内部更相似，不会让所有种族迅速同质化。

### 6.2 第二层：当前存档已配置但尚未生成的 Race/Xenotype

新档刚开始或某个 Race 刚被“阵营种族多样性”启用时，世界中可能还没有该 Race 的 Pawn。如果只扫描现有人物，基因池会为空。

回退来源按优先级为：

1. “阵营种族多样性”中该阵营启用且权重大于 0 的 Race/Xenotype；
2. HAR Race 的 `xenotypeList`、`whiteXenotypeList`；
3. 对应 `PawnKindDef.xenotypeSet`；
4. 对应 `FactionDef.xenotypeSet`；
5. 与 Race 明确关联且通过 HAR `CanUseXenotype` 的 `XenotypeDef`；
6. 当前 Pawn 自己的可遗传异种类型基因。

这些 Def 级来源只作为“没有足够现有人物样本时的种群先验”，实际出现的 Pawn 仍然拥有更高权重。

### 6.3 第三层：突变池

突变池不是“随便从所有 GeneDef 抽一个”，而应满足：

- 当前存档常见基因池中尚未出现；
- `canGenerateInGeneSet == true`；
- `selectionWeight > 0`；
- 默认 `biostatArc == 0`；
- 不是黑名单基因；
- 通过目标 Race 的 HAR 系谱基因兼容判定；
- 不与现有核心基因冲突；
- 代谢合法；
- 自定义 `geneClass` 与身体结构基因满足额外安全规则。

突变候选按 `GeneDef.selectionWeight` 加权，避免所有基因等概率。已在当前世界出现后，它会在下一次基因池刷新时成为“常见基因”，从而形成真正会扩散的世界遗传历史。

### 6.4 缓存与性能

不应每生成一个 Pawn 就完整扫描世界。

建议：

- `WorldComponent` 持有只读快照；
- 载入世界后首次需要时懒加载；
- 每 60,000 ticks（约 1 游戏日）刷新一次；
- 玩家修改本模组设置或“阵营种族多样性”设置后立即失效；
- Def 级 Race/Xenotype 关联表只在 Def 加载完成后构建一次；
- 热路径中不做全程序集反射，不用大规模 LINQ 临时分配。

初版无需把整个频率表写入存档；它可以从当前世界 Pawn 重建。只保存设置与以后可能加入的“旧档手动处理记录”。

## 七、候选基因安全校验

建议实现统一的 `GD_GeneSafetyValidator`，所有常见池、突变池、出生突变都必须经过同一条安全链。

### 7.1 基础校验

候选必须满足：

1. `gene != null`；
2. Pawn 有基因追踪器；
3. Pawn 为人形；
4. 当前没有同一个系谱基因或异种基因；
5. 默认排除 `EndogeneCategory.Melanin` 与 `EndogeneCategory.HairColor`；
6. 默认排除 `GeneDefOf.Inbred`，近亲基因继续只由原版关系算法产生；
7. 默认排除 `biostatArc > 0`；
8. `canGenerateInGeneSet == true`；
9. 前置基因已存在，否则跳过；初版不自动额外塞入前置链；
10. 与当前所有核心基因无 `ConflictsWith` 冲突；
11. 加入后，按实际系谱/异种类型计算的未覆盖基因总代谢仍在 -5～+5；
12. 如果请求要求战斗能力，排除会禁用 `WorkTags.Violent` 的候选；
13. `pawn.genes.AddGene(gene, false)` 返回 null 时视为被 HAR 或其他模组拒绝，安静换下一个候选，但在详细日志中可记录原因。

### 7.2 为什么不能只调用 `GeneSet.CanAddGeneDuringGeneration`

`GeneSet.CanAddGeneDuringGeneration` 很有参考价值，会检查：

- 重复；
- 代谢范围；
- `canGenerateInGeneSet`；
- 前置基因；
- 冲突。

但它不知道：

- 当前 Pawn 的 Race；
- HAR 白名单/黑名单；
- 基因是系谱还是异种；
- 当前 Pawn 已有的异种基因覆盖关系；
- 战斗角色保护；
- 自定义基因类的 Race 假设。

因此应复用原版规则的思想，但为实际 Pawn 做完整校验。

### 7.3 自定义基因类与身体结构基因

第三方 `GeneDef.geneClass` 可能访问特定：

- BodyPart；
- Hediff；
- HAR Comp；
- Race 专属颜色通道；
- 月相、资源、能力或特殊 Gizmo；
- 其他程序集中的类型。

保守规则：

1. `geneClass == typeof(Gene)` 的普通基因可进入一般候选；
2. 自定义 `geneClass` 默认只允许：
   - 在其原生 Race 上出现；或
   - 兼容配置明确声明可跨 Race；
3. 耳朵、尾巴、身体、头型、外观渲染类基因默认只在原生 Race 内传播；
4. 不复制第三方 GeneDef；只在其来源模组已加载时引用实际 Def；
5. 来源模组卸载后，由原版存档清理缺失 Def；发布说明必须提示不要在仍有相关 Pawn 时随意卸载基因来源模组。

## 八、推荐 Harmony 接入点

### 8.1 新生成 Pawn 的个体差异

推荐补丁：

```csharp
[HarmonyPatch(typeof(PawnGenerator), "GenerateGenes")]
[HarmonyAfter("rimworld.erdelf.alien_race.main")]
internal static class GD_Patch_PawnGenerator_GenerateGenes
{
    static void Postfix(Pawn pawn, XenotypeDef xenotype, PawnGenerationRequest request)
    {
        // 在原版异种基因、强制基因与 HAR raceGenes 都已装入后，
        // 在身体类型、装备与最终校验之前增加少量系谱变体。
    }
}
```

选择这个位置的理由：

- 最终 Race 与异种类型已经确定；
- “阵营种族多样性”已经完成请求改写；
- HAR 的 `raceGenes` 已经加入；
- 加基因仍发生在身体类型、装备和最终 validator 之前；
- 如果某个基因使 Pawn 不适合该请求，原版生成重试机制仍可工作；
- 不需要改写 `PawnGenerator.GenerateGenes` 的 IL。

处理保护：

- `request.AllowedDevelopmentalStages.Newborn()` 时跳过，避免对出生结果再随机一次；
- `ForcedCustomXenotype != null` 时默认跳过，尊重玩家精确设计；
- 明确 `ForcedEndogenes`/`ForcedXenogenes` 的特殊请求默认跳过；
- 只有 `ForcedXenotype` 时不必跳过，因为“阵营种族多样性”会用它传递最终异种类型；本模组不改变该异种类型，只追加安全变体；
- 可通过自建排除 Def/ModExtension 排除任务专用 PawnKind、Faction 或 Race。

### 8.2 新生儿的低概率突变

原版遗传已经足够好，不应重写 `GetInheritedGenes`。推荐只在真正出生时做一次低概率突变：

```csharp
[HarmonyPatch(typeof(PregnancyUtility), nameof(PregnancyUtility.ApplyBirthOutcome))]
internal static class GD_Patch_ApplyBirthOutcome
{
    static void Prefix(ref List<GeneDef> genes, Pawn geneticMother, Pawn father, Thing birtherThing)
    {
        // genes 非空时先复制列表，绝不直接修改怀孕/胚胎保存的 GeneSet。
        // 默认 10% 几率增加 1 个通过安全校验的突变系谱基因。
    }
}
```

关键规则：

- `genes = new List<GeneDef>(genes)` 后再改，不能污染怀孕 Hediff 或胚胎原始基因表；
- 双胞胎/多胞胎每个孩子独立判定突变；
- 没有突变时完全保持原版结果；
- 不重算父母遗传，不改变原版 50%/100% 规则；
- Epona 等出生后修正异种类型的模组仍可在 Postfix 中工作；本模组只改变传给生成请求的系谱基因列表。

如果实测发现某个模组向 `ApplyBirthOutcome` 传入 null，但又需要突变，则该兼容应单独处理，不能在 Prefix 中擅自再次调用 `GetInheritedGenes`，以免消耗随机数并生成与怀孕记录不一致的结果。

### 8.3 不推荐的接入点

- 不推荐在 `PawnGenerator.GeneratePawn` Postfix 才加基因：此时装备与 validator 已完成，可能产生“战士生成后失去暴力能力”之类不一致。
- 不推荐直接 Postfix `GetInheritedGenes`：该方法也用于怀孕基因预览、胚胎与其他中间流程，随机突变可能被重复计算。
- 不推荐 Transpiler 修改原版遗传循环：维护成本高，且 HAR、Epona 等已有补丁更容易发生 IL 冲突。

## 九、HAR 兼容结论

### 9.1 HAR 自身已经提供最终防线

HAR 1.6 会 Patch `Pawn_GeneTracker.AddGene(Gene, bool)`，在实际加入前调用：

```text
RaceRestrictionSettings.CanHaveGene(gene.def, pawn.def, addAsXenogene)
```

它会检查：

- 通用基因白名单/黑名单；
- 系谱基因专用白名单/黑名单；
- 异种基因专用白名单/黑名单；
- `exclusionTags` 前缀；
- `EndogeneCategory` 黑名单；
- 化学品是否可由该 Race 使用。

因此，本模组使用正常的 `pawn.genes.AddGene(gene, false)` 时，HAR 会自动拒绝不兼容基因。新模组仍应通过反射提前调用 `CanHaveGene`，减少无效候选；但真正的最终裁决仍以 HAR 的 AddGene Prefix 为准。

### 9.2 HAR Race 的专属基因

HAR 在原版 `PawnGenerator.GenerateGenes` 中注入 `GenerateGenesForcedHelper`，把 `generalSettings.raceGenes` 作为系谱基因加入 Race Pawn。

本模组的 Postfix 位于其后，因此可以：

- 看见已经加入的 Race 核心基因；
- 避免重复；
- 把这些基因计入当前 Race 的常见基因池；
- 不覆盖 HAR 的发色/肤色通道修正。

### 9.3 HAR 兼容适配器

不要硬引用 HAR DLL。建议像“阵营种族多样性”的 `FRD_HarCompatibility` 一样使用一次性反射：

- 查找类型 `AlienRace.RaceRestrictionSettings`；
- 缓存静态方法 `CanHaveGene(GeneDef, ThingDef, bool)`；
- 缓存 `CanUseXenotype(XenotypeDef, ThingDef)`；
- 读取 Race 的 `alienRace.raceRestriction.xenotypeList`、`whiteXenotypeList`、`blackXenotypeList`；
- 读取 `generalSettings.raceGenes` 作为 Race 原生基因来源；
- 反射失败时只对 Human 使用通用候选，非 Human 采取保守“不跨 Race 添加”回退，并只记录一次警告。

## 十一、与“阵营种族多样性”的兼容方案

已核对现有模组：

- 模组名：阵营种族多样性（Faction Race Diversity）
- `packageId`：`yyyyy.mixedpeoplesfactions`
- Harmony ID：`yyyyy.factionracediversity`

其关键行为是：

1. 在 `PawnGenerator.GenerateOrRedressPawnInternal` Prefix 中原子选择最终 Race、PawnKind 与 Xenotype；
2. 通过 `FRD_RaceRegistry` 枚举人形 Race；
3. 通过 `FRD_XenotypeService` 与 `FRD_HarCompatibility` 获取 Race 可用 Xenotype；
4. 最终把选择写入 `PawnGenerationRequest`，再交给原版生成。

### 11.1 执行顺序

推荐顺序：

```text
阵营种族多样性：选择最终 Race / PawnKind / Xenotype
        ↓
原版 PawnGenerator：创建最终 Race 的 Pawn
        ↓
原版 + HAR GenerateGenes：安装异种核心基因与 Race 基因
        ↓
基因多样性：追加少量安全系谱变体
        ↓
原版：身体类型、装备、最终校验
```

所以新模组绝不能在更早阶段自己重新选 Race 或 Xenotype。

### 11.2 复用现有公开服务

现有程序集已经公开：

- `FRD_RaceRegistry.HumanlikeRaces`
- `FRD_RaceRegistry.GetKinds(race)`
- `FRD_XenotypeService.GetAllowedXenotypes(race)`
- `FRD_XenotypeService.IsSafeForRace(...)`
- `MPF_Mod.Settings`
- `MPF_Settings.GetFactionSettings(...)`
- 各阵营 `raceWeights` 与各 Race 的异种权重

推荐新模组通过**可选反射适配器**读取这些数据，不产生硬程序集依赖：

- 已加载时：把权重大于 0 的 Race/Xenotype 纳入当前存档 Def 级基因池；
- 未加载时：退回现有人物 + 原版/HAR 自动发现；
- 适配失败时：只警告一次，不阻止 Pawn 生成。

### 11.3 推荐给旧模组补一个稳定 API

为了减少未来反射字段变化，可在“阵营种族多样性”下一次更新中增加只读接口，例如：

```csharp
public static class FRD_IntegrationApi
{
    public static IReadOnlyList<ThingDef> GetEnabledRaces(FactionDef faction);
    public static IReadOnlyList<XenotypeDef> GetEnabledXenotypes(FactionDef faction, ThingDef race);
    public static bool WasXenotypeSelectedByFRD(PawnGenerationRequest request);
}
```

初版基因模组不必等待这个 API；先对当前公开服务做反射适配即可。

### 11.4 必须避免的冲突

- 不修改 `FRD_RaceCompatibilityDef` 的 Race/PawnKind 映射职责；
- 不在基因模组里复制 18 个 HAR Race 的 PawnKind 兼容表；
- Race/Xenotype 归属以“阵营种族多样性”的最终结果为准；
- 基因模组只维护“哪些基因可作为某 Race 的常见/突变候选”；
- 如果某 Race 在种族多样性设置中权重为 0，它不应仅因已加载 Def 就自动成为该阵营的高权重基因来源。

## 十二、与“阵营文化多样性”的兼容方案

已核对现有模组：

- 模组名：阵营文化多样性
- `packageId` / Harmony ID：`yyyyy.factionculturaldiversity`

它主要：

- 在 `PawnGenerator.TryGenerateNewPawnInternal` 维护生成请求上下文；
- 在 `PawnGroupKindWorker.GeneratePawns` 维护队伍上下文；
- 在首次 `Pawn_IdeoTracker.SetIdeo` 时选择个人文化；
- 不修改 Race、Xenotype 或 Gene。

新模组主要 Patch `PawnGenerator.GenerateGenes` 与 `PregnancyUtility.ApplyBirthOutcome`，目标方法不同，职责正交，原则上不会冲突。

### 12.1 三个模组同时启用时的最终模型

一个普通袭击者可以依次获得：

1. **阵营种族多样性**：决定他是 Human、Ratkin、Kiiro、Milira、Wolfein 等 Race，并决定对应异种类型；
2. **基因多样性**：在该 Race/异种类型核心基因上增加少量可遗传个体差异；
3. **阵营文化多样性**：在不改变政治阵营的前提下决定其个人文化。

最终形成真正的三层多样性：

```text
政治阵营
 ├─ 多种文化
 ├─ 多种 Race
 └─ 每种 Race / Xenotype 内部仍有个体基因差异
```

### 12.2 不建议做自动“文化—基因绑定”

初版不应根据文化评分、模因或戒律提高某些基因概率。原因：

- 文化模组的核心原则是个人文化不改变政治/生物身份；
- 自动把文化与基因绑定会产生难以解释的反馈与社会含义；
- 会让两个本来可独立使用的模组互相成为事实依赖。

如果未来玩家确实需要，可作为显式关闭的高级兼容功能，例如“某文化偏好某些已存在的异种类型”，但不应进入初版。

## 十五、存档兼容与移除行为

### 15.1 新旧存档

- 新档：正常生效；
- 旧档：只影响以后新生成 Pawn 与以后出生的孩子；

## 十六、开发阶段划分

### 阶段 1：最小可运行闭环

目标：只支持原版 Human/Xenotype。

实现：

- `GenerateGenes` Postfix；
- 当前世界系谱基因池；
- 90/10 候选选择；
- 代谢、冲突、前置、发色/肤色、超凡、战斗安全；
- 新生成 Pawn 0～3 个变体；
- 不做出生突变、不做 HAR、不做旧档补充。

验收：

- 同异种类型 Pawn 出现少量不同系谱基因；
- 核心异种类型不变；
- 无红字；

## 十七、完整测试矩阵

### 17.1 原版最小环境

加载：Core + Biotech + Harmony + 基因多样性。

测试：

- 智人、猪人、妖魔、尼安德特人、土鼹人、废土人等；
- 可遗传与不可遗传异种类型；
- 阵营 Pawn、无阵营 Pawn、起始殖民者、难民、奴隶、商人；
- 强制战斗角色；
- `ForcedCustomXenotype`；
- `ForcedEndogenes` / `ForcedXenogenes`；
- 保存、读取、退出再进入。

通过现象：

- Race/Xenotype 标签不被替换；
- 核心基因不丢失；
- 新增基因均为系谱基因；
- 代谢不越界；
- 无重复发色/肤色；
- 战斗 Pawn 不因新增基因失去暴力能力；
- 无生成耗尽或 post-gear validator 红字。

### 17.2 原版遗传

组合：

1. 父母都有同一新增变体；
2. 只有父亲有；
3. 只有母亲有；
4. 父母不同可遗传异种类型；
5. 父母同一可遗传异种类型；
6. 一方/双方为不可遗传异种类型；
7. 代谢接近 -5 或 +5；
8. 近亲；
9. 双胞胎；
10. 胚胎与成长舱。

通过现象：

- 同基因为 100%，单亲为约 50%的统计分布；
- 超凡基因不自然继承；
- 肤色/发色仍由原版流程处理；
- 混血标签与同异种类型继承正常；
- 出生突变只在设定概率触发且最多一个。

### 17.3 HAR 通用

- HAR + 一个无基因扩展的普通 Alien Race；
- Race 白名单允许/拒绝测试；
- 系谱专用黑名单；
- `EndogeneCategory` 黑名单；
- 化学品限制；
- Race 自带 `raceGenes`；
- HAR 未安装回归。

### 17.4 已知基因扩展

每个模组都做：

- 本体单独；
- 本体 + Gene Patch；
- 本体 + Gene Patch + 阵营种族多样性；
- 同 Race 100%；
- Human 0%；
- 多 Race 混合；
- 普通袭击、军事援军、访客、商队、商人、领袖、世界 Pawn；

重点：

## 十八、风险与对应措施

| 风险 | 后果 | 措施 |
|---|---|---|
| 随机基因破坏异种身份 | 所有异种逐渐同质化 | 不删除核心基因；同 Race/同阵营高权重；结构基因同 Race 限制 |
| 自定义 Gene 类假设特定 Race | NullReference、缺 BodyPart、错误 Gizmo | 自定义类默认同 Race；精确兼容白名单 |
| HAR 拒绝基因 | AddGene 返回 null | 反射预检 + AddGene 最终防线 + 有限重试 |
| 代谢越界 | 怀孕失败、生成校验异常 | 每次候选加入前计算实际未覆盖基因总代谢 |
| 战士获得非暴力基因 | 装备被移除、袭击 validator 失败 | 战斗请求排除 `WorkTags.Violent` 禁用基因 |
| 出生突变重复计算 | 预览与实际不一致 | 只 Patch `ApplyBirthOutcome`，不 Patch 通用预览函数 |
| 修改怀孕 GeneSet 本体 | 双胞胎与存档被污染 | Prefix 中复制 `List<GeneDef>` |
| Race Diversity 强制 Xenotype 被误判为任务固定 | 所有联动 Pawn 被跳过 | 不因 `ForcedXenotype` 单独跳过；只保护自定义/强制基因与显式排除项 |
| 当前世界扫描太频繁 | 卡顿与 GC | 世界快照每游戏日刷新；Def 表静态缓存 |
| 旧档批量污染 | 不可逆改动 | 默认不回填；手动工具另做并记录处理 ID |
| 来源基因模组被卸载 | Pawn 丢失相关 Def | 不复制 Def；发布说明提示来源依赖；记录来源名称用于诊断 |

## 十九、最终推荐的初版边界

为了让项目尽快形成稳定闭环，建议第一个可发布版本只做以下内容：

1. 保留原版 Race 与 Xenotype；
2. 新生成非新生儿 Pawn 有 0～3 个额外系谱变体；
3. 每个位点 90% 来自当前世界常见池、10% 来自兼容突变池；
4. 默认不含超凡、发色、肤色、近亲、自定义类和跨 Race 结构基因；
5. 通过代谢、前置、冲突、战斗与 HAR 安全检查；
6. 自然后代由原版机制继承这些变体；
7. 出生时另有默认 10% 的单基因突变；
8. 默认只处理新人物，不自动处理旧人物；
9. 初版不新增任何功能 GeneDef；
10. 与前两个多样性模组都采用软兼容，不建立硬程序集依赖。

这个边界已经能实现用户最核心的体验：

> 同一异种类型不再人人完全相同；世界中常见的遗传特征会扩散，罕见突变会偶尔出现，并能通过原版父母遗传继续形成家系。
