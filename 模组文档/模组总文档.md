## 1. 模组定位

本模组不重新随机整套 Race 或 Xenotype，而是在原有核心身份上追加少量安全、可遗传的 Endogene 差异。世界中已经实际存在的遗传特征会继续扩散，低概率突变会引入新特征，后续传承仍交给原版生育系统。

永久优先级：

1. 当前存档实际 Pawn 的 Endogenes；
2. 同 Race、同阵营来源权重最高；
3. 目标 Race 没有实际样本时才使用 Race/Xenotype Def 回退；
4. 明确的低概率突变机制才使用突变池；
5. 候选不安全时宁可少加或不加，绝不删除核心基因或放宽 Race/冲突/前置/代谢规则。

## 2. 阶段 1：新生成 Pawn 个体差异

Patch：`PawnGenerator.GenerateGenes(Pawn, XenotypeDef, PawnGenerationRequest)` Postfix。

- 合格 Pawn 抽取 0～3 个位点，概率为 20%/55%/20%/5%；
- 每个位点 90% 使用当前世界常见池，10% 使用突变池；
- 每个位点最多尝试 20 个不同候选；
- 新基因通过 `pawn.genes.AddGene(candidate, false)` 成为 Endogene；
- Newborn、ForcedCustomXenotype、非空 ForcedEndogenes/ForcedXenogenes、无 gene tracker Pawn 跳过；
- 普通 ForcedXenotype 不单独跳过；
- 战斗请求继续保护 Violent 工作能力。

阶段 1 已由用户于 2026-07-28 验收通过。

## 3. 阶段 2：真正出生时单基因突变

Patch：RimWorld 1.6 的 `PregnancyUtility.ApplyBirthAutcome` 全 11 参数签名，`Priority.Last` Prefix。

- 只处理非 null `genes` 且父母为原版 Human 的出生；
- 每次合格调用只投一次 10% 骰子；
- 命中后最多尝试 20 个官方安全突变候选；
- 只有找到合法候选时才复制 `new List<GeneDef>(genes)` 并最多追加 1 个 Endogene；
- 不原地修改怀孕、胚胎、多胎或成长舱共享的 GeneSet；
- 不调用 `GetInheritedGenes`，不改写原版父母遗传。

阶段 2 已由用户于 2026-07-28 验收通过。阶段 3 没有修改 `GD_BirthMutationPatch.cs`、`GD_BirthMutationUtility.cs` 或 `GD_MetabolismUtility.cs`；三者 SHA-256 仍与阶段 2 回滚基线一致。

## 4. 阶段 3：HAR 通用兼容

### 4.1 软兼容与保守降级

- 项目不引用 `AlienRace.dll`，程序集引用列表不含 HAR；
- `GD_HarAdapter` 从已加载程序集一次性寻找 HAR 类型与方法，并把 `CanHaveGene`、`CanUseXenotype` 建成基类参数委托；
- Gene/Race 与 Xenotype/Race 判定结果按 Race 缓存；
- HAR 未安装：原版 Human 继续阶段 1/2 路径，非 Human 不进入随机追加；
- HAR 检测到但适配失败：只警告一次并熔断，原版 Human 保留，非 Human 保守跳过。

### 4.2 当前世界系谱池

世界快照每 60,000 ticks 刷新，扫描 `PawnsFinder.AllMapsWorldAndTemporary_Alive.ToList()`：

- 仅存活、Humanlike、有 gene tracker 的原版 Human 与 HAR Pawn；
- 只统计 Endogenes，不统计 Xenogenes；
- 同一 Pawn 只统计一次；
- 保存 Gene、来源 Race、来源 Faction、次数和候选类别；
- 目标 Pawn 的权重为：同阵营同 Race ×4、同 Race ×2、其他已出现 Race 的普通标准基因 ×1；
- 自定义 geneClass、结构/外观基因不跨 Race 扩散；
- 目标 Race/Faction 的加权候选表在当前快照内缓存，避免每个 Pawn 重复构建。

阶段 2 使用的原版 Human 常见池与官方突变池单独保留，因此 HAR 接入不会把出生突变改成第三方全 Def 随机。

### 4.3 HAR Race 回退

目标 HAR Race 没有实际系谱样本时，低权重读取：

1. `alienRace.generalSettings.raceGenes` 的静态可能项；
2. `raceRestriction.xenotypeList` 与 `whiteXenotypeList`；
3. 排除 `blackXenotypeList`，并再次调用 `CanUseXenotype`。

读取 `raceGenes` 时只看 `entry/options/count/chance` 字段；不会调用 `AlienChanceEntry.Select` 或 `Approved`，因此不会消耗随机数或改动 HAR 的 `shuffledAptions` 缓存。世界实际 Pawn 来源的最低权重仍高于 Def 回退。

### 4.4 安全裁决

候选按三类处理：

- 标准 `geneClass == typeof(Gene)`：可低权重跨 Race，但仍需全部安全检查；
- 自定义 geneClass：只允许已在目标 Race 实际观察到或由该 Race 明确回退来源声明；
- 结构/外观基因：同样只允许目标 Race 已观察/声明，不跨 Race。

所有候选最后还必须通过：重复、双向冲突、前置、覆盖后代谢、Violent、HAR `CanHaveGene(gene, race, false)`。真正加入时 HAR 的 `Pawn_GeneTracker.AddGene` Prefix 仍拥有最终否决权；返回 null 时只换候选，不绕过 HAR。

### 4.5 Patch 顺序与出生边界

- `GD_PawnGenerationPatch` 标注 `[HarmonyAfter("rimworld.erdelf.alien_race.main")]`，在 HAR raceGenes 与其生成逻辑之后追加差异；
- 阶段 3 只扩展非新生儿 HAR Pawn 生成；
- HAR 出生额外 10% 突变未实现，因为 Prefix 阶段不能可靠确定 HAR 多胎/替换 PawnKind 后的最终孩子 Race；不会用母亲 Race 猜测。

## 9. 阶段 4：已知 HAR 基因来源精确兼容

阶段 4 在阶段 3 通用启发式之上增加 `GD_RaceGeneCompatibilityDef` 与 `GD_CompatibilityRegistry`。它不会复制或修改第三方 GeneDef，而是用本模组自己的 XML 记录精确来源关系。

### 9.1 精确规则

- Kiiro：`Kiiro_Race → KiiroXenotype`；
- Milira：`Milira_Race → MiliraXenotype`；
- Wolfein：只使用可遗传 `Wolfein_Xenotype`，排除 `Wolfein_PureBlood` 身份基因，月相等自定义类只在 Wolfein 内；
- Ratkin Gene Expanded：只登记当前 1.6 的八个可遗传鼠族异种类型；
- OA Ratkin：统一使用 `OAGene_*` Def 名；只把七个明确可遗传的普通鼠族异种类型（含 `OAGene_RatkinBase`）作为 Def 回退，自定义/结构/身体依赖基因只在 Ratkin 内，并排除 `OAGene_BiochemicalRatkinI`；
- Epona：基础 Epona、Unicorn、Destrier 与两个 Milira 混血 Race 分别拥有独立 Xenotype 池。

### 9.2 与世界系谱的关系

精确 Def 是低权重先验与边界，不改变最高优先级：当前存档实际 Pawn 的 Endogenes 仍按同阵营同 Race ×4、同 Race ×2、其他 Race 标准基因 ×1 形成候选。目标 Race 已有实际样本时不会用 Def 回退压过世界历史。

### 9.3 软兼容与加载

- 六个来源只加入 About.xml 的可选 `loadAfter`，不加入硬依赖；
- XML 使用 `MayRequire`；
- C# 只比较 packageId 和 Def 名，不引用任何第三方程序集类型；
- 来源未加载、依赖缺失或 Def 名不存在时静默不注册对应规则；
- 精确 Race 存在时，HAR `raceGenes` 仍可作为种族固有来源，但通用 Xenotype 列表不再覆盖精确白名单。
