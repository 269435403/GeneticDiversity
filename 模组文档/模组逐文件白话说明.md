## 1. 根目录

### `AGENTS.md`

以后所有 Agent 的强制开发约束。最重要的是当前存档系谱优先、HAR 与 Human 同等适用、候选不安全时宁可不加。

### `build.ps1`

寻找 RimWorld 与 Harmony，执行 Release 构建。产物直接写到开发主副本 `1.6/Assemblies/`。系统限制脚本执行时用 `-ExecutionPolicy Bypass`。

### `.gitignore`

忽略 bin/obj 等中间产物。运行副本不会包含它。

## 2. About 与运行文件

### `About/About.xml`

声明 RimWorld 1.6、Biotech 与 Harmony 硬依赖；HAR、阶段 4 已验收来源与阶段 4.5 十个新增来源只在 loadAfter 中出现，属于可选软兼容。

### `1.6/Defs/Compatibility/GD_KnownHarGeneSources.xml`

阶段4的 Kiiro、Milira、Wolfein、Ratkin Gene Expanded、OA Ratkin 精确兼容 Def。**可改，但必须与第三方 1.6 Def 名同步核对，改后刷新 Wiki。**

### `1.6/Defs/Compatibility/GD_EponaRacePools.xml`

阶段4的 Epona、Unicorn、Destrier 与两个 Milira 混血 Race/Xenotype 分池规则。**可改，但不得把基础池和混血池合并。**

### 1.6/Defs/Compatibility/GD_Phase45HarGeneSources.xml

阶段 4.5 十来源精确规则。每条使用 MayRequire 软加载，只登记实际活动的 Race/Gene/Xenotype Def；Moosesian 因 XML 当前不在游戏加载根而没有条目。

### 1.6/Languages/ChineseSimplified/DefInjected/GeneticDiversity.GD_RaceGeneCompatibilityDef/GD_Phase45Compatibility.xml

兼容 Def 的简体中文名与说明。目录名必须使用完整 C# Def 类型名，否则 Wiki 生成器和游戏 DefInjected 不能匹配。**可改，改后刷新 Wiki。**

## 3. Source/GeneticDiversity

### `GeneticDiversity.csproj`

.NET Framework 4.8 项目，只引用 Assembly-CSharp、UnityEngine.CoreModule 和 0Harmony。没有 AlienRace.dll 引用。

### `GD_HarmonyBootstrap.cs`

用固定 Harmony ID PatchAll。长事件结束后初始化阶段4精确兼容注册表，并输出 HAR 与六来源检测状态。

### `GD_PawnGenerationPatch.cs`

新人物入口。显式 Patch `GenerateGenes(Pawn, XenotypeDef, PawnGenerationRequest)`，并用 HarmonyAfter 等待 HAR。保留 Newborn/强制基因等跳过条件；Human 直接允许，非 Human 必须是已成功适配的 HAR Humanlike Race。

### `GD_GeneSelector.cs`

负责 0～3 位点、每位点 90% 常见/10% 突变、最多 20 次不同候选。真正 AddGene 返回 null 时把该候选加入本 Pawn 的拒绝集合，继续换候选但不死循环。

### `GD_WorldGenePool.cs`

阶段 3～4 核心：

- 保留阶段 1/2 使用的原版 Human 常见池与官方突变池；
- HAR 可用时扫描当前世界 Human/HAR Endogenes；
- 记录 Race、Faction、次数、标准/自定义/结构类别；
- 为目标 Pawn 建立 4/2/1 加权池；
- 自定义和结构候选不跨 Race；
- 目标 Race 无样本时，优先按阶段4精确 Def 读取原生 Xenotype/Gene；没有精确规则才使用 HAR 通用 Xenotype 回退；
- 快照每游戏日刷新，Race/Faction 目标池在快照内缓存。

### `GD_HarAdapter.cs`

无硬依赖 HAR 适配器：

- 从已加载程序集找 HAR 类型；
- 核对两个静态方法签名并创建委托；
- 按 Race 缓存 CanHaveGene/CanUseXenotype；
- 反射读取 raceRestriction、generalSettings、raceGenes；
- 只读取 AlienChanceEntry 字段，不调用 Select/Approved；
- 任一关键能力失败时只警告一次并熔断，非 Human 保守跳过。

### `GD_GeneSafetyValidator.cs`

Pawn 入口同时处理 Human/HAR：先应用阶段4精确排除与同种族规则；标准候选才可低权重跨 Race，自定义/结构候选必须属于目标 Race；随后检查重复、双向冲突、前置、覆盖后代谢、Violent 和 HAR CanHaveGene。

出生列表入口保持阶段 2 原版规则，不扩展 HAR。

### `GD_MetabolismUtility.cs`

把现有 Xenogenes、Endogenes 和候选转成 GeneDefWithType，通过 `NonOverriddenGenes()` 计算最终有效代谢与 Violent 禁用。阶段 3 未修改此文件。

### `GD_BirthMutationPatch.cs`

精确绑定 11 参数 ApplyBirthOutcome，Priority.Last Prefix。阶段 3 未修改。

### `GD_BirthMutationUtility.cs`

一次 10% 判定、最多 20 个候选、复制源列表、最多追加 1 个官方安全 Endogene。阶段 3 未修改。

### `GD_Diagnostics.cs`

只累计聚合数字：Human/HAR 合格 Pawn、Race、同 Race/跨 Race/Def 回退添加、CanHaveGene 拒绝、适配失败、AddGene null、阶段 2 出生统计等。

### `GD_DebugActions.cs`

提供缓存操作、成年人物地图统计、HAR 适配器报告、世界系谱按种族摘要，以及第二阶段历史诊断按钮。按钮名和屏幕消息使用准确中文。


### `GD_Phase3AutomatedTests.cs`（历史文件，已删除）

第三阶段验收期间曾提供全套一键测试。日志和结果记录完成后，该测试辅助文件已按规则删除，最终运行版本不再包含这些临时按钮。历史步骤见 `测试/阶段3白话测试方案.md`。


### `GD_RaceGeneCompatibilityDef.cs`

阶段4自定义 Def 类型。保存来源 packageId、目标 Race、原生 Xenotype/Gene、排除项、同种族项、跨种族安全项和排除 PawnKind；所有字符串用 `GetNamedSilentFail` 安全解析。**可改，但字段名改动必须同步 XML 与 Wiki。**

### `GD_CompatibilityRegistry.cs`

阶段4运行时注册表。合并同一 Race 的多个可选来源规则，建立精确原生池与结构/自定义基因所有者边界；来源卸载时保持零活动规则。**高风险可改：不得降低世界实际系谱优先或绕过 HAR。**

### `GD_Phase4AutomatedTests.cs`（历史文件，已删除）

阶段 4 验收期间曾提供 12 个只读一键测试按钮，负责六来源检测、每来源边界、结构/自定义基因、Epona-Milira 分池和卸载软降级。用户日志完成判定和正式记录后，该文件已按测试生命周期规则删除；当前源码结构不再包含它。历史步骤和结果保存在 `测试/阶段4白话测试方案.md`、原始日志副本与正式验收记录中。

### GD_Phase45AutomatedTests.cs（当前临时测试文件，验收前不得删除）

阶段 4.5 的中文只读 Debug Action：十来源检测与精确边界、Nivarian 自动非标准基因所有者边界、纯内存正式 4/2/1 世界优先级回归，以及 一键执行阶段4.5当前组合全部只读测试 总入口。当前用于收集用户日志；验收记录完成后才删除并重建。
### `GD_Log.cs`

统一 `[GeneticDiversity]` 日志前缀。

## 阶段 6 收尾（2026-07-30）

本阶段把前五阶段的固定行为整理为可持久化设置，并补齐只读统计和旧档主动补充工具。默认值保持前五阶段行为：启用、玩家/NPC 均启用、标准强度、突变比例 10%、新生儿突变概率 10%、普通功能基因允许跨种族、特殊/外观/身体基因默认不跨种族、详细日志关闭、Archite 突变关闭。

旧档工具不会自动回填，也不直接修改存档 XML。玩家必须在游戏内主动点击并二次确认，建议先另存测试档。工具会跳过婴儿、任务专用人物和无基因追踪器人物，并在世界组件中按 `thingIDNumber` 记录已处理人物以防重复追加。移除模组前应保留备份；如需彻底清除处理记录，应在游戏内使用“清除旧档已处理记录”。

阶段 6 临时测试入口在用户日志判定完成前保留。
