## 0. 永久核心规则

随机可遗传变体必须优先使用当前存档实际 Pawn 的 Endogenes。原版 Human 与 HAR Race 同等适用。固定权重为同阵营同 Race ×4、同 Race ×2、其他已出现 Race 的标准基因 ×1；Def 回退不得压过世界实际样本。

完整约束见根目录 `AGENTS.md` 与 `核心设计公约.md`。

## 4. HAR 必须保持软兼容

- `GeneticDiversity.csproj` 禁止引用 AlienRace.dll；

  - `AlienRace.RaceRestrictionSettings.CanHaveGene(GeneDef, ThingDef, bool)`；

## 5. raceGenes 只读规则

`generalSettings.raceGenes` 是 `List<AlienChanceEntry<GeneDef>>`。

禁止调用：

- `Select`；
- `Approved`；
- 任何会消耗 Rand 或改动 `shuffledOptions` 的方法。

只允许读取 `entry`、`options`、`count`、`chance`：chance ≤ 0 的条目排除；direct entry 不受 count 影响；count ≤ 0 时不递归 options。这里只得到“静态可能项”，实际加入仍要经过 Race、重复、冲突、前置、代谢与 AddGene 裁决。

## 7. 候选分类与安全

### 标准候选

`geneClass == typeof(Gene)`，无 bodyType、forcedHeadTypes、forcedHair 或定义的图形属性。可跨 Race 低权重传播，但必须通过全部安全检查与 HAR CanHaveGene。

### 自定义 geneClass

只允许目标 Race 当前世界实际观察过，或该 Race 的 raceGenes/允许 Xenotype 明确声明。未知来源与其他 Race 来源拒绝。

### 结构/外观候选

bodyType、forcedHeadTypes、forcedHair、定义图形属性等默认只在同 Race 传播，并要求实际观察或明确 Race 回退来源。

所有候选继续排除发色、肤色、Inbred、超凡；要求 `canGenerateInGeneSet`，检查重复、双向 ConflictsWith、prerequisite、覆盖后代谢和 Violent。`AddGene` 返回 null 时安静换候选，禁止绕过 HAR。

## 8. 回退权重

目标 Race 无实际系谱观察时：

- HAR Race：raceGenes + 明确允许 Xenotype；
- Human：阶段 1 官方可遗传 Xenotype 常见池；
- Def 回退基础权重低于任何当前世界观察；
- 回退为空时允许少加或不加；
- 阶段 3 不扫描全部第三方 GeneDef 建 HAR 通用池。

## 16. 本会话 PowerShell / C# 避坑补充

- **正则路径转义**：PowerShell -notmatch '\Languages\|' 会把 \L 视为非法正则转义并报 Unrecognized escape sequence \L。优先用 $path.Contains('\Languages\')；必须用正则时写 \\Languages\\，并设置 $ErrorActionPreference = 'Stop'，防止脚本带错继续。
- **递归枚举过滤**：Get-ChildItem -Recurse -File -Include ... 在部分调用方式下不会严格筛掉其他文件，可能把 DLL 送入 Get-Content。应先枚举文件，再用 Where-Object { .Name -eq '目标文件名' } 或明确目录的 -Filter。
- **反射命名空间**：C# 使用 FieldInfo、BindingFlags 等反射类型时必须添加 using System.Reflection;；不要因为同项目其他文件已引用就假定当前文件可见。
- **批量文档写回验证**：不要把 PowerShell 辅助函数命名为 Write，避免与输出语义混淆或只打印未写回。统一直接调用 [IO.File]::WriteAllText(...)，写回后必须复读目标文件和关键状态句验证，不能只相信控制台无报错。
- **PowerShell 插值变量后接冒号**：双引号字符串写 `$p:$line` 时，解析器会尝试把 `p:` 当作变量/驱动器限定名并报“Variable reference is not valid”。应写 `${p}:$line`，或优先使用格式运算符 `'{0}:{1}' -f $p,$line`。
- **DLL 元数据字符串编码**：直接把整个 .NET DLL 字节按 UTF-16LE 解码会漏掉大多数用户字符串，造成按钮字符串“未找到”的假失败；程序集元数据字符串堆使用 UTF-8。扫描按钮名时应按 UTF-8 字节/字符串检索，或使用能读取 .NET 元数据的工具，并用已知新旧字符串做正反向校验。
